# n8n Web deployment package — Gold Intelligence (9 workflows)

> **Status: PACKAGE PREPARED. NOT PRODUCTION-READY.**
> "Production-ready" requires all three remaining live checks to pass on the running instance:
> the first scheduled PRE_EVENT run, the first scheduled DAILY_REPORT run and the AI fallback health.
> Check them with `node tools/verify-live.js` (local pilot) or `sh deploy/n8n-web/verify.sh` (server).
> See [docs/CONTINUATION_STATE.md](../../docs/CONTINUATION_STATE.md).

**Final import package:** [deploy/n8n-final/](../n8n-final/). It holds the 9 numbered workflows, the manifest,
`IMPORT_ORDER.md` and `verify-package.sh`. This runbook covers the server around it.

This package deploys the same system that was live-verified locally: the same workflow JSON (byte-identical,
rebuilt from `src/`), schema, seeds and configuration, with no redesign. It contains no secrets. Every secret
is a placeholder that the owner fills in on the server.

## 1. Target

**"n8n Web" means self-hosted n8n 1.117.2 on a Linux server (VPS), with the n8n editor reachable in a browser
over HTTPS**, run by Docker Compose together with PostgreSQL. This path needs no code change.

**n8n Cloud (the hosted n8n.io service) is NOT supported by the current build.** Each of these blocks it:

| Blocker | Why |
|---|---|
| Secrets and settings come from `$env` | 35 Code nodes and the schedule-hour expressions read `TELEGRAM_BOT_TOKEN`, `OPENROUTER_API_KEY` and every `GI_*` setting from `$env`. n8n Cloud does not let you set environment variables, and blocks `$env` in nodes. On Cloud, Telegram and AI would be NOT_CONFIGURED and every setting would fall back to its default. |
| Fixed workflow ids | Sub-workflow calls, the error workflow and the credential are referenced by fixed id (§6). Cloud has no CLI import, and editor import assigns new ids. |
| Execution volume | The six schedules start about **105 000 production executions per 30 days**: Telegram Bot every 30 s ≈ 86 400; Health every 5 min 8 640; Market 10 min 4 320; News 15 min 2 880; Pre-Event refresh 1 440 + daily 30; Post-Event 1 440; Daily 30. Compare this with the plan's monthly execution quota. |
| Database | An external PostgreSQL reachable from n8n Cloud over the internet (TLS) would be required. The bootstrap sets `ssl: disable` for the private Compose network. |

Moving to n8n Cloud would be a separate change: `$env` → `$vars` in the config loader, id remapping, and a
bot-polling redesign or a higher plan. It is not part of this package.

## 3. Server requirements

* Linux x86_64, Docker Engine with the Compose v2 plugin, git.
* **2 vCPU, 4 GB RAM recommended (2 GB minimum), 10 GB disk.** On the owner's PC the pilot ran under memory
  pressure (0.5 GB free; the task runner failed with 403 until it was switched off). A clean replica used about
  300 MB for n8n and 60 MB for PostgreSQL at idle, and the database starts at about 12 MB.
* Outbound HTTPS to `api.telegram.org`, `openrouter.ai` and the data sources in [SOURCE_MAP.md](../../SOURCE_MAP.md)
  (gold-api.com, Coinbase, Treasury, BLS, BEA, Federal Reserve, CFTC, news feeds).
* Inbound: none is required. Telegram uses long polling. Open 443 only if the editor is published through a
  reverse proxy (§7); otherwise use an SSH tunnel.
* The image `docker.n8n.io/n8nio/n8n:1.117.2` is pinned. If that registry is unreachable, set
  `N8N_IMAGE=n8nio/n8n:1.117.2` (Docker Hub) in `.env`.

## 4. Credential placeholders

All values live only in the server's `.env` (created from `.env.example`, `chmod 600`, never committed). n8n
reads the secrets from its process environment. The Postgres login is also stored as the n8n credential
**GI Postgres** (id `GIpostgresCred01`), encrypted with `N8N_ENCRYPTION_KEY`. The bootstrap creates it from
`.env`; you never type it into the editor.

| Variable | Placeholder | Where it comes from | Notes |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | `<TELEGRAM_BOT_TOKEN>` | BotFather | use the **regenerated** token (the old one was pasted into a chat) |
| `TELEGRAM_CHAT_ID` | `<TELEGRAM_CHAT_ID>` | owner's chat id | comma-separated list of authorised chats; the first receives alerts |
| `OPENROUTER_API_KEY` | `<OPENROUTER_API_KEY>` | openrouter.ai → Keys | use the **regenerated** key; one key only, no rotation |
| `FRED_API_KEY` | `<FRED_API_KEY>` (optional) | fred.stlouisfed.org | enables WTI, VIX and broad-dollar series |
| `GI_PG_PASSWORD` | `<GI_PG_PASSWORD>` | `openssl rand -hex 24` | used by PostgreSQL, n8n's own DB and the GI Postgres credential |
| `N8N_ENCRYPTION_KEY` | `<N8N_ENCRYPTION_KEY>` | `openssl rand -hex 32` | **keep it stable and back it up.** Without it, stored credentials and n8n backups are unreadable |
| `N8N_HOST`, `N8N_PROTOCOL`, `N8N_EDITOR_BASE_URL`, `N8N_SECURE_COOKIE` | `<n8n.example.com>`, `https`, `https://<n8n.example.com>`, `true` | your domain | only when the editor is published over HTTPS (§7) |

Keep these values as in `.env.example`: `GENERIC_TIMEZONE=Africa/Casablanca`, `TZ=Africa/Casablanca`,
`GI_PREEVENT_DAILY_HOUR=6`, `GI_DAILY_REPORT_HOUR=7`, `OPENROUTER_PRIMARY/SECONDARY/TERTIARY_MODEL` (the verified chain).

## 5. Database requirements

* PostgreSQL **16** (the Compose service; the pilot ran on 18.4). No extensions.
* Two databases on the same server, both owned by `GI_PG_USER` (default `gold_intel`):
  * `gold_intel` — system data: 27 tables and 5 views after `sql/*.sql`;
  * `n8n` — n8n's own tables (workflows, credentials, executions).
* Initial content, loaded by `deploy/postgres-init/01-init.sh`:
  * 362 `historical_event_reactions`;
  * ≥ 6 135 `market_observations` and ≥ 2 156 `gold_observations` (to 2026-09-26);
  * 26 `sources`.
* `schema_migrations` lists only 001, 002, 003 and 010. Migrations 004 (AI usage) and 005 (calibration) do not
  write a row. Check that their tables exist (`ai_usage`, `ai_model_health`, `calibration_cells`); the row count
  is not a valid check.
* The database session timezone is UTC. Local-day logic uses `Africa/Casablanca` explicitly.
* Retention: n8n prunes executions after 14 days (`EXECUTIONS_DATA_MAX_AGE=336`). Back up `gold_intel` daily (§10).

## 6. Import order and method

**Workflow ids must be kept.** The workflows call each other by fixed id:
* `giAiAnalystSub01` and `giTelegramSend01` are called by Execute Workflow nodes;
* `giErrorHandler01` is the error workflow of the other eight;
* `GIpostgresCred01` is the credential of every Postgres node.

**Use the n8n CLI (`n8n import:workflow`), never the editor's "Import from file"**, which creates new ids and
silently breaks those links.

| # | Item | File | Active |
|---|---|---|---|
| 0 | credential **GI Postgres** | built from `.env` (or `credentials.template.json`) | — |
| 1 | GI · Error Handler | `gold-intelligence-error-handler.json` (`giErrorHandler01`) | no (error workflow) |
| 2 | GI · Telegram Sender (sub-workflow) | `gold-intelligence-telegram-sender.json` (`giTelegramSend01`) | no (called) |
| 3 | GI · AI Analyst (sub-workflow) | `gold-intelligence-ai-analyst.json` (`giAiAnalystSub01`) | no (called) |
| 4 | GI · Health Monitor | `gold-intelligence-health.json` (`giHealthMonitor1`) | **yes** — every 5 min |
| 5 | GI · Master Pipeline (news + market) | `gold-intelligence-master.json` (`giMasterPipeline`) | **yes** — news 15 min, market 10 min |
| 6 | GI · Pre-Event Engine (forecasts) | `gold-intelligence-pre-event.json` (`giPreEventEngine`) | **yes** — daily 06:00, refresh 30 min |
| 7 | GI · Post-Event Review | `gold-intelligence-post-event.json` (`giPostEventRevw1`) | **yes** — 30 min |
| 8 | GI · Daily Report | `gold-intelligence-daily.json` (`giDailyReport001`) | **yes** — daily 07:00 |
| 9 | GI · Telegram Bot (commands) | `gold-intelligence-telegram-bot.json` (`giTelegramBot001`) | **yes** — 30 s |

The order puts dependencies first: the error handler and sub-workflows, then monitoring, then the data jobs, then
the user-facing bot. Activate in the same order, so health data exists before the bot answers `/status`. Times
are Africa/Casablanca.

### A. New server with Docker Compose (recommended)

The bootstrap performs steps 0–9 and the activations automatically on the first boot.

### B. Existing self-hosted n8n (no Compose)

1. That n8n must run with the variables from `.env.example` in its process environment, including
   `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`.
2. Apply `sql/*.sql` and the two seeds to a `gold_intel` database.
3. Import the credential and the workflows:
   ```sh
   cp deploy/n8n-web/credentials.template.json /tmp/gi-cred.json   # fill the <…> placeholders, then:
   n8n import:credentials --input=/tmp/gi-cred.json && rm -f /tmp/gi-cred.json
   for f in error-handler telegram-sender ai-analyst health master pre-event post-event daily telegram-bot; do
     n8n import:workflow --input="workflows/gold-intelligence-$f.json"
   done
   for id in giHealthMonitor1 giMasterPipeline giPreEventEngine giPostEventRevw1 giDailyReport001 giTelegramBot001; do
     n8n update:workflow --id="$id" --active=true
   done
   ```
4. Restart n8n. Activation takes effect on start.

## 7. Deployment steps (Compose)

```sh
# 1. Server: Docker + Compose plugin + git installed; a non-root user in the docker group.
git clone https://github.com/Livaey-777/N8N_trading.git gold-intelligence && cd gold-intelligence
git checkout <verified commit or tag>                  # pin exactly what was verified

# 2. Configuration (secrets never leave the server)
cp .env.example .env && chmod 600 .env
sed -i "s/^GI_PG_PASSWORD=.*/GI_PG_PASSWORD=$(openssl rand -hex 24)/" .env
sed -i "s/^N8N_ENCRYPTION_KEY=.*/N8N_ENCRYPTION_KEY=$(openssl rand -hex 32)/" .env
nano .env        # TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, OPENROUTER_API_KEY (+ FRED_API_KEY); do not echo them
cp .env ~/gold-intelligence.env.backup && chmod 600 ~/gold-intelligence.env.backup   # keep off-server too

# 3. CUTOVER — only ONE instance may run the schedules. Stop the local pilot first:
#    two instances would split the bot's Telegram updates and send duplicate alerts / reports.
#    On the PC:  node tools/n8n-local.js stop

# 4. Start
docker compose pull
docker compose up -d
docker compose logs -f n8n-bootstrap      # ends with: credential + workflows imported, schedules activated
docker compose ps                          # postgres healthy, n8n healthy, n8n-bootstrap exited (0)

# 5. Owner account: open the editor (SSH tunnel:  ssh -L 5678:127.0.0.1:5678 <server>  → http://localhost:5678)
#    and create the owner on the first visit.
```

The server starts from the seeds. Forecast memory, AI-usage history and the Telegram log start empty, and the
calibration cells are rebuilt by the first Daily Report. Local pilot data is not migrated.

**HTTPS editor (optional).** Keep `127.0.0.1:5678` and put a TLS reverse proxy in front of it. Caddy example:
`n8n.example.com { reverse_proxy 127.0.0.1:5678 }`. Then set `N8N_HOST`, `N8N_PROTOCOL=https`,
`N8N_EDITOR_BASE_URL` and `N8N_SECURE_COOKIE=true` in `.env` and run `docker compose up -d --force-recreate n8n`.

## 9. Rollback

Before every deployment or change: `sh deploy/n8n-web/backup.sh` (both databases plus the commit and image ids),
and keep `.env` (it holds `N8N_ENCRYPTION_KEY`).

**R1 — a workflow change misbehaves** (instance otherwise fine):
```sh
git checkout <previous commit> -- workflows/
docker compose run --rm --entrypoint n8n n8n-bootstrap import:workflow --separate --input=/gi/workflows
# n8n's import DEACTIVATES every imported workflow (verified on 1.117.2) — re-activate the six schedules:
for id in giHealthMonitor1 giMasterPipeline giPreEventEngine giPostEventRevw1 giDailyReport001 giTelegramBot001; do
  docker compose run --rm --entrypoint n8n n8n-bootstrap update:workflow --id="$id" --active=true
done
docker compose restart n8n                 # "Start Active Workflows" must list all six
git checkout HEAD -- workflows/            # back to the current files in the working tree
```

**R2 — the whole deployment misbehaves** (return to the last backup):
```sh
docker compose stop n8n
B=backups/<timestamp>
docker compose exec -T postgres sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists' < $B/gold_intel.dump
docker compose exec -T postgres sh -c 'pg_restore -U "$POSTGRES_USER" -d "${N8N_DB_DATABASE:-n8n}" --clean --if-exists' < $B/n8n.dump
git checkout "$(sed -n 's/^commit=//p' $B/meta.txt)"
docker compose up -d
sh deploy/n8n-web/verify.sh
```

**R3 — abandon the server, back to the local pilot:**
1. On the server: `docker compose stop n8n`. Do this **first**; never run both instances at once.
2. On the PC: `node tools/n8n-local.js start`, then `/status` from the phone.
3. Keep the server volumes (`docker compose down` without `-v`) until the cause is known.

Never run `docker compose down -v`: it deletes both databases.

## 10. Operations

| Task | Command |
|---|---|
| status | `docker compose ps` · Telegram `/status` · `sh deploy/n8n-web/verify.sh` |
| logs | `docker compose logs -f n8n` |

| AI model no longer free / listed | set `OPENROUTER_*_MODEL` in `.env`, recreate n8n (see [AI_MODELS.md](../../AI_MODELS.md)) |

Notes from the replica test:
* n8n's default listen address `::` crash-loops on hosts without IPv6. The Compose file sets
  `N8N_LISTEN_ADDRESS=0.0.0.0` (the port is still published on 127.0.0.1 only).
* The first boot takes a few minutes (each activation boots the n8n CLI). The "Activation … will not take
  effect if n8n is running" lines in the bootstrap log are expected: n8n is not running yet.
